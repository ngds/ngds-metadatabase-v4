##Database Build

	createuser ngdsdb;
	createdb geothermal -O ngdsdb;
	createdb pycsw -O ngdsdb;
	alter user ngdsdb with password 'xxx';

	CREATE USER py_fdw WITH password 'xxx';
	GRANT CONNECT ON DATABASE pycsw to py_fdw;
	
##Import data from production

pg_dump --file "geothermal.sql" --host "10.208.3.120" --port "5432" --username "ngdsdb" --no-password --verbose --format=p  --create "geothermal"

pg_dump --file "pycsw.sql" --host "10.208.3.120" --port "5432" --username "ngdsdb" --no-password --verbose --format=p  --create "pycsw"

Then import to new:

psql -U postgres -d geothermal < /home/ec2-user/database/geothermal.sql

psql -U postgres -d pycsw < /home/ec2-user/database/pycsw.sql

PyCSW
Port: 8000

For this version, pyCSW documentation can be found at:

https://docs.pycsw.org/en/2.6.1/index.html

sudo docker pull geopython/pycsw:2.4.2

Note: Current pyCSW uses a modified database schema and is not compatable with NGDS.

sudo docker container run  -detach -p 8000:8000 geopython/pycsw:2.4.2

sudo docker update --restart=always <container_id>

1- Within the docker container, edit the /etc/pycsw/pycsw.yml file.

comment out the default sqllite and add the postgresql connection string:

database: 'postgresql://ngdsdb:<password>@10.221.154.98/pycsw2'

Add identifying info for contact, organization, etc as desired. Whebn complete:

sudo docker cp pycsw.yml <container id>:/etc/pycsw

2 - apiso issues is a known bug -

https://github.com/geopython/pycsw/issues/576

In order to correct, use the apiso.py found in the NGDS github. Other versions will not 
function correctly. Without correction, the display XML functions display "invalid XML" errors.

sudo docker cp apiso.py <container id>:/etc/pycsw/pycsw/pycsw/plugins/profiles/apiso.py 

Then restart container, monitor the docker container logs to verify correct functioning. 

To complete, perform command line test:

http://127.0.0.1:8000

This will return a Summary GetCapabilities in XML format. Check for errors.

Verify command success in the docker logs which are found at:

/var/lib/containers/<container-id>/<container-id>-json.logs
